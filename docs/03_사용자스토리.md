# 회의실 예약 서비스 사용자 스토리

### S1. 겹치는 예약 막기
- 스토리: 회의실을 예약하는 사용자로서, 이미 예약된 시간과 겹치는 예약을 막고 싶다. 같은 시간에 중복 예약되는 것을 방지하기 위해서다.
- 인수 조건:
  - 기존 예약과 시간이 겹치는 예약은 거절된다.
  - 겹침의 정확한 판단 기준(예: 한 예약의 종료 시각과 다른 예약의 시작 시각이 같은 경우)은 **확인 필요**.

### S2. 정원을 넘는 예약 막기
- 스토리: 회의실을 예약하는 사용자로서, 참석 인원이 정원을 초과하는 예약을 막고 싶다. 회의실 정원에 맞게 이용하기 위해서다.
- 인수 조건:
  - 참석 인원이 회의실 정원을 초과하는 예약은 거절된다.

### S3. 예약 현황판 웹페이지 만들기
- 스토리: 회의실을 이용하는 사용자로서, 웹페이지에서 예약 현황을 확인하고 싶다. 회의실 예약 상황을 파악하기 위해서다.
- 인수 조건:
  - 예약 현황을 확인할 수 있는 웹페이지를 제공한다.
  - 현황판에 표시할 정보와 공개 범위는 **확인 필요**.

### S4. 예약 취소 기능 만들기
- 스토리: 예약을 관리하는 사용자로서, 예약을 취소할 수 있기를 원한다. 더 이상 필요하지 않은 예약을 정리하기 위해서다.
- 인수 조건:
  - 예약을 취소할 수 있는 기능을 제공한다.
  - 취소할 수 있는 사람과 취소 후 처리 방식은 **확인 필요**.

### 확인 필요
- **최대 예약 시간(2시간 또는 4시간):** 강도윤 팀장이 정책을 확정하기로 함.
- **노쇼 자동 취소 기준 시간(10분 또는 15분) 및 이번 범위 포함 여부:** 회의록에 결정 담당자가 명시되지 않아 담당자 확인 필요.
- **현황판에 연락처를 표시할지와 외부 공개 여부:** 회의록에 결정 담당자가 명시되지 않아 담당자 확인 필요.
